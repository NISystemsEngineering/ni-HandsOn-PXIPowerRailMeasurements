# Firmware projects

ESP-IDF source projects for the ESP32-C6-DevKitC-1-N8 DUT used in the PXI power-rail hands-on session.

**You do not need these to run the session.** Prebuilt images for all four exercises are already in
`../PXI_Training/exercises/`, and the batch files in `../PXI_Training/` flash them. Use these projects
only to change a provided image or to build different firmware.

## Projects

| Project folder | Builds the image in | Flashed by | Used in | What it does |
| --- | --- | --- | --- | --- |
| `deep_sleep_forever` | `PXI_Training/exercises/sleep_current/` | `1_Flash_and_Monitor_SLEEP.bat` | Exercise 1 | Puts the DUT into deep sleep so the SMU can measure sleep current (expect roughly 10 to 20 µA) |
| `NimBLE_Beacon` | `PXI_Training/exercises/beacon/` | `2_Flash_and_Monitor_BEACON.bat` | Exercises 2 and 3 | Repeats a BLE advertising event: three ADV_IND packets, one each on channels 37, 38 and 39. Advertising is non-connectable and non-scannable, so the radio does not wait for scan requests and the current bursts are clean and repeatable |
| `NimBLE_Beacon_triggered` | `PXI_Training/exercises/beacon_triggered/` | `3_Flash_and_Monitor_BEACON_TRIGGERED.bat` | Exercise 4 and both instructor demos | Same advertising as `NimBLE_Beacon`, plus a pulse on GPIO10 before each advertising event, which the scope uses as its trigger |

## Build environment

- ESP-IDF **v6.0.2**, target **esp32c6**. Install with Espressif's EIM installer.
- Build from the ESP-IDF terminal that EIM sets up (the prompt starts with `(venv)`).
- Full instructions: *FAE Setup Manual*, Appendix B (`docs/presenter/`).

## Rebuilding a provided image

1. Open the ESP-IDF terminal and change to the project folder, for example `firmware\NimBLE_Beacon_triggered`.
2. Change settings if needed with `idf.py menuconfig`, or edit the source in `main\`.
3. Run `idf.py build`.
4. Copy the new `build` folder over the matching one under `PXI_Training/exercises/` (see the table above).
   The batch files flash that copy, so an old copy keeps running the old firmware.

**Do not run `idf.py set-target` on these projects.** They are already set up for `esp32c6`, and
`set-target` regenerates `sdkconfig` from defaults, which erases the settings below.

The first build after the repo is cloned or moved rebuilds everything and takes a few minutes.

## Settings that matter (`NimBLE_Beacon_triggered`)

These are stored in the project's `sdkconfig`, which is committed to the repo.

| Setting | `sdkconfig` key | Value | Why |
| --- | --- | --- | --- |
| Brownout detector level | `CONFIG_ESP_BROWNOUT_DET_LVL_SEL_3` | Level 3, about 3.10 V | Sets where the DUT resets in Exercise 4 |
| NimBLE host log level | `CONFIG_BT_NIMBLE_LOG_LEVEL_WARNING` | Warning | Keeps the serial monitor quiet so the brownout message stands out |

In menuconfig, press `/` and search for the key without the `CONFIG_` prefix to find each setting.

## What is not in the repo

Each project's `build/` folder is excluded by `.gitignore`: it is regenerated by `idf.py build` and is
large. The flashable output lives in `PXI_Training/exercises/` instead.
